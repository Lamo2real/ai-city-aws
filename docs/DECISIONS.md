# Decisions

One line each: the decision, and why. "Owner" means the owner chose it in conversation before
the build; "Build" means it was chosen during the overnight build.

## Owner's decisions (recorded as given)
1. **Dedicated new AWS account** for AI City. The owner confirms the account before the first deploy.
2. **Budget $150/month, daily global cap $10.** Starting values only: heavy use of Fable and Opus will need higher caps.
3. **No connection to the owner's Mac.** Nothing in this product reaches it.
4. **Workers run isolated in AgentCore microVMs with the policy gate on** (setting `policy_applies_to_workers`, default true).
5. **Global inference profiles.** Cheapest, and the only way to reach Fable from Europe. Prompts may be processed outside the EU. The prefix is one config value (`profilePrefix` in `config/models.json`, `profile_prefix` in Terraform); switching to `eu.` makes Fable roles fall back to Opus 5.5.
6. **Cognito web login over CloudFront** with MFA; the web app is the only public entry point.
7. **Private GitHub repo** for the code.
8. **Start with empty memory.** Nothing imported from the Mac.
9. **Single `prod` environment.**
10. **Anthropic models only**, as pinned in `config/models.json`: AIC Sonnet 5.5, Orchestrator and Managers Fable 5.1 (Opus 5.5 fallback), Workers Opus 5.5, utility Haiku 5.5.

## Build decisions
11. **Region `eu-north-1`.** Facts check confirmed Runtime, Memory, Gateway, Identity, built-in tools and Observability there.
12. **Transcribe and Polly are AWS speech services, not language models**, so they do not conflict with "Anthropic models only".
13. **Voice through a Cognito identity pool** scoped to `transcribe:StartStreamTranscriptionWebSocket` and `polly:SynthesizeSpeech` only (ADR 0006). Simpler and lower latency than a Lambda proxy.
14. **Workers' web search uses the SDK's WebSearch/WebFetch**, because the AgentCore Gateway Web Search connector is not in Stockholm.
15. **Application inference profiles per role, with a switch.** Created from global profiles; if AWS refuses a global source at deploy, `use_application_inference_profiles = false` falls back to calling global profiles and the ledger carries per-role cost.
16. **Fable fallback is one retry on Opus 5.5 per turn**, recorded in the ledger (`fallback: true`). Refusal or no verdict never loops.
17. **Cache TTL:** 1-hour prompt cache for orchestrator and managers (their turns are event-driven and minutes apart), 5-minute for AIC and workers (continuous turns). Cost math supports both.
18. **`CLAUDE_CODE_DISABLE_1M_CONTEXT=1`** everywhere; long sessions compact at 60 % of a 200k window with a Haiku summary.
19. **Runtimes invoked with IAM (SigV4) from Lambda only**, not JWT: only the dispatcher talks to AgentCore, so no inbound JWT config is needed on runtimes.
20. **Ledger is one DynamoDB table** (`aic-prod-ledger`) with `pk`/`sk` plus two GSIs (`gsi1` by status, `gsi2` by department); spend counters are separate items updated atomically with `ADD` and a condition.
21. **Daily caps are per UTC day**, as in upstream; the HUD shows Stockholm time beside it.
22. **Per-department daily cap default $5**, global $10, monthly $150. A department cap above the global cap is pointless and is rejected by Settings.
23. **Concurrency defaults:** 100 workers per department, 2,450 global (2,500 Stockholm quota − 50), 20 new sessions per second (quota 25).
24. **Turn timeout 15 minutes** for synchronous turns (AgentCore request timeout); long worker jobs run async up to 8 h, with a 7.5 h soft limit so the worker reports before AgentCore kills it.
25. **SQS visibility timeout 16 minutes** (turn timeout + 1 minute), DLQ after 3 receives.
26. **Departments are data.** `config/departments.json` is an empty seed; the Orchestrator creates them.
27. **Docker is not installed on the build machine**, so the image was not built tonight; the Dockerfile is written and checked by a unit test that parses it (arm64, port 8080, non-root user).
28. **tflint and checkov installed locally** with Homebrew/pip to run the offline checks (they are local tools, not cloud calls). If installation failed it is listed in the morning report.
29. **HUD state in a plain reducer** ported from upstream `city-state.js`, so the City view is unit-tested in Node.
30. **The City view canvas renderer is ported from upstream `city.js`** (pixel art drawn in code, no image assets), changed for the new cast: AIC in the plaza where Jarvis stood, Orchestrator at the HQ door, Secretary and Reviewer removed.
31. **Ledger writes from workers** go only through the `report_to_manager` / `ask_manager` tools, which put events on the bus; the ledger Lambda writes them. Workers have no DynamoDB permission at all (stricter than "only their own hire record").
32. **Step Functions approvals** use `waitForTaskToken`; the token is stored on the approval item and returned when the owner approves in the HUD.
33. **EventBridge Scheduler jobs are created with `state = "DISABLED"`** (retire idle agents, weekly self-improvement, reminders sweep).
34. **Self-improvement loop: built, disabled, and fenced** — its changed-file check refuses any path under `infra/`, IAM, `config/caps.json`, `config/policy.json` and `.github/`.
35. **Pause flag** lives in the ledger (`CONFIG#city`), read by the dispatcher before every turn; `scripts/city-off.sh` sets it and disables the SQS event source mappings.
36. **No Reviewer and no Secretary agents.** Managers review; the Orchestrator signs off; AIC summarizes.
37. **Bedrock throttling** is retried with full-jitter exponential backoff (base 1 s, cap 30 s, 5 tries), never a pause. "Spend cap reached" is the only pause from spend.
38. **TypeScript pinned ~6.0.3**, because typescript-eslint 8.72 supports TypeScript below 6.1 only.
39. **A fourth queue for AIC** (`aic-prod-ace`), next to the orchestrator, manager and worker queues, so owner messages and results pass the same pause/cap checks as every other turn.
40. **Managers get an `answer_worker` tool** beside the listed ones; without it a worker's `ask_manager` question had no way back.
41. **`gh pr merge` is denied for every agent** (upstream: ask), because the owner merges PRs into `main`.
42. **Cloud mutation from agents is denied, not asked** (upstream asked for `aws ... delete-*` and `terraform destroy`/`apply ... prod`). An owner approval can never unlock a deny rule.
43. **Instructions copy the manager on the record, without waking it**, so an `@agent` instruction costs one turn, not two.
44. **The stale-lease sweep** (scheduled job `sweep`) re-sends messages whose turn crashed; it gives back the dead worker's concurrency slot.
45. **AIC's role can write the ledger and send to the queues.** The prompt lists "read ledger status" for AIC, but AIC's own tools (delegate a task, answer a question, notes, pause) write tickets and messages. Its role still has no Factory, no S3, no secrets.
46. **Worker ledger writes are limited by key prefix** (`dynamodb:LeadingKeys`): tickets, its own agent/turn/tool records, work leases, spend counters, slots, approval *requests*. Workers cannot write settings (pause, caps), departments, specialists, questions or owner approvals. Owner approvals are separate `APPROVED#<hash>` items only the API writes; a worker can only consume (delete) one. Residual: a worker can update another worker's `AGENT#wkr-*` record (documented in SECURITY.md).
47. **Workers reach S3 only by assuming `aic-prod-worker-workspace` with a `hire_id` session tag**; that role is limited to `hires/${aws:PrincipalTag/hire_id}/*`.
48. **The Factory's function name is fixed** (`aic-prod-factory`), so the agents module gets its ARN without depending on the api module (avoids a cycle).
49. **The HUD's `config.json` is written by Terraform** into the site bucket with public values only (endpoints, client and pool IDs).
50. **Log retention 30 days** (variable), not checkov's suggested 1 year, to keep cost low; the ledger is the durable record.
51. **The site bucket uses SSE-S3**, not the KMS key, so CloudFront OAC can read it without a cross-service key policy; it holds only public app files.
52. **WAF also gets AWS's KnownBadInputs rule set** besides the common rules, IP reputation and a 1,000-requests-per-5-minutes rate limit.
53. **In deploy.yml the image is pushed before `terraform apply`** (inside the approved job), because the reviewed plan points the runtimes at that image tag; applying first would point them at an image that does not exist yet.
54. **The deploy role has AdministratorAccess fenced by a boundary and its trust**: only `deploy.yml` on `main` in the `production` environment (owner approval) can assume it; the boundary denies Organizations, account, IAM users/access keys and CloudTrail tampering. Terraform must manage IAM, KMS and Cognito, so a narrower policy was not attempted tonight.
55. **Commit messages carry `[skip ci]` at the end of the subject line**, followed by the Co-Authored-By trailer (git trailers must be the last paragraph). GitHub skips workflows when `[skip ci]` appears in the message, and every workflow is `workflow_dispatch`-only anyway.
56. **No spend limit (the owner's choice, 2026-11-06).** City spend caps are off by default (`null` = no limit) and stay optional in Settings; when set they are still checked before every turn. AWS Budgets only emails at 50/80/100 % + forecast: the deny-Bedrock budget action and the budget Lambda that paused the city are removed. Concurrency ceilings (100 per department, 2,450 total, 20 new sessions/s) stay: they protect AgentCore quotas, not spend. Supersedes part of ADR 0010.
57. **AWS Budgets alert amount $10,000 / month (the owner's choice, 2026-11-06)**, replacing $150. Emails at 50/80/100 % ($5k / $8k / $10k) and on a forecast above it; still alerts only, nothing is blocked or paused. Set in `prod.tfvars` (`monthly_budget_usd`) or the GitHub variable `AIC_MONTHLY_BUDGET_USD`; Terraform allows up to $10,000.
58. **No bootstrap; the deploy needs only the role ARN (2026-11-06).** The owner provides the OIDC deploy role (trust in `docs/deploy-role-trust-policy.json`). `deploy.yml` creates the Terraform state bucket `aic-prod-tfstate-<account>-<region>` on its first run (`scripts/ensure-state-bucket.sh`: private, versioned, SSE-KMS with the AWS-managed key, TLS-only; native S3 lockfile). The agent image is built and pushed by `terraform_data.image` during apply, after the ECR repository and before the runtimes, so one reviewed plan deploys from nothing. Replaces `infra/bootstrap` and the two-step first deploy; supersedes the deploy-role part of decision 54. The state bucket is the one resource created before the owner approves a plan.
59. **Owner email as a secret, state in `lamo-labs-state-bucket` (the owner's choice, 2026-11-06).** The repository is public, so workflow logs are public: `AIC_OWNER_EMAIL` is a GitHub secret (masked in logs) and the full plan is printed to the log instead of being uploaded as `plan.txt`. The binary plan artifact still holds it for 3 days (needed to apply exactly the reviewed plan). State key `ai-city-aws/prod/terraform.tfstate` so the bucket can hold other projects; an existing bucket is used as it is and its own region is passed to the backend.
60. **Push to `main` deploys prod, without approval (the owner's choice, 2026-11-06).** `deploy.yml` runs on pushes to `main` (docs-only pushes skipped via `paths-ignore`) and by hand, never on pull requests; the `production` environment stays for deployment history without required reviewers. The image tag is `rt-<hash of the runtime sources>`, so pushes that don't touch the runtime don't rebuild the image or replace the runtimes. Supersedes the manual-only rule and the `[skip ci]` commit rule (decision 55); `[skip ci]` now means "don't deploy this push". Agent sessions still never deploy on their own: they push to `main` only when the owner asks.
61. **The deploy role trusts GitHub's immutable OIDC subject** (2026-11-06). The repository issues tokens with `sub = repo:Lamo2real@143636021/ai-city-aws@1448210802:<ref or environment>` (owner and repository IDs), so the trust matches that exactly, for `ref:refs/heads/main` and `environment:production`. The first deploy failed on the older `repo:Lamo2real/ai-city-aws:...` form. The `job_workflow_ref` condition was dropped: the subject already pins the repository and branch.
62. **The application is Python (the owner's choice, 2026-11-06).** Shared core, Lambdas and the AgentCore runtime moved from TypeScript to Python 3.13 in `backend/` (package `aic`, managed by `uv`; ruff, mypy, pytest). Pydantic replaces zod for event schemas; PyJWT replaces aws-jwt-verify for the WebSocket authorizer; Starlette + uvicorn serve the runtime; the Claude Agent SDK for Python bundles the Claude Code CLI, so the image has no Node.js. Behaviour and wire formats are unchanged (events, API JSON, DynamoDB items, queue messages keep their keys). All Lambdas share one zip built for arm64 (boto3 comes from the runtime). The React HUD and the Node-based repo checks (`check-tags.mjs`, `check-iam.mjs`, infra/workflow vitest tests) stay as they are; the wake-word parity test now uses `tests/fixtures/wake-cases.json`.
63. **Our own sign-in screens (the owner's choice, 2026-11-06).** Cognito's hosted pages confused the owner, so the HUD signs in itself with Amplify Auth v6 (`aws-amplify/auth`): SRP, the NEW_PASSWORD_REQUIRED step, TOTP setup (QR code from `qrcode`) and codes, forgot-password, token refresh, tokens in sessionStorage. The app client allows `ALLOW_USER_SRP_AUTH` only (refresh token rotation forbids `ALLOW_REFRESH_TOKEN_AUTH`; Amplify refreshes with `GetTokensFromRefreshToken`); the hosted domain stays but is unused. The invitation and reset emails are rewritten in plain steps; temporary passwords last 7 days. A public, rate-limited `POST /auth/first-login-email` re-sends the invitation (Cognito `AdminCreateUser` with `RESEND`) only for the owner's email and answers the same for any email. Playwright drives the screens with a fake AuthClient (`window.__aicAuth`); real Cognito is checked at the first real sign-in. AIC's look is one eye, the owner's own drawing (`web/public/ace-eye.png`, used as a CSS mask so each state can colour and move it).
64. **Knowledge base: Bedrock Knowledge Base on S3 Vectors + a DynamoDB graph, all in Stockholm (the owner's choice, 2026-11-07).** Contract in `docs/KNOWLEDGE.md`. Facts checked 2026-11-07 (AWS Price List API, eu-north-1; Bedrock and Neptune docs):
    - **Vectors:** S3 Vectors is in Stockholm ($0.06/GB-month, $0.20/GB written, $0.0025 per 1,000 queries; nothing fixed). OpenSearch Serverless was rejected: $0.255 per OCU-hour with a 2-OCU minimum for classic collections ≈ $372/month idle.
    - **Embeddings:** Anthropic has no embedding model, so the owner allowed one exception to "Anthropic models only": Amazon Titan Text Embeddings V2 (in-Region in Stockholm, $0.021 per million tokens, 1,024 dimensions), pinned under `embeddings` in `config/models.json`. It only turns text into vectors; all reading, summarizing and entity extraction is Claude Haiku 5.5. Cohere Embed v4 needs cross-Region inference from Stockholm.
    - **Graph:** the owner first chose Neptune Analytics, but Bedrock's managed GraphRAG is not offered in Stockholm (only Frankfurt, London, Ireland, Oregon, N. Virginia, Tokyo, Singapore), and the smallest Neptune Analytics graph in Stockholm (16 m-NCU, $0.581/h) costs ≈ $424/month running. The owner then chose the cheap option: Haiku 5.5 extracts entities and relationships into a DynamoDB table, and search widens vector hits one hop through that graph. Neptune Analytics stays a later upgrade (`docs/KNOWLEDGE.md` §13).
    - **Parsing and media:** the Bedrock Data Automation parser is only in us-west-2 (preview), so scanned PDFs and images are read by Haiku 5.5 vision; audio and video go through Amazon Transcribe batch (in Stockholm), with MediaConvert extracting audio first from video and from containers Transcribe doesn't take (such as `.mov`).
    - **Importance:** three scopes per item: `always` (summary in every agent's prompt, 8,000-token budget), `relevant` (default, found by search), `on_request` (only when the owner asks).
    - **Safety:** stored content is untrusted data, returned inside `<knowledge>` tags with a "data, not instructions" line; only AIC can add items (when the owner asks), so worker-fetched content can't feed itself into the store; link fetching refuses private and metadata addresses.
    - **Cost:** light personal use (2 GB of documents, 10 hours of video and 3,000 searches a month) is an estimated $15–25/month, mostly Transcribe ($0.024/min); $0 when idle.
65. **The knowledge pipeline is started by the knowledge Lambda, not straight from EventBridge (2026-11-07).** EventBridge rule targets cannot set a Step Functions execution name (only the input), and the contract wants one run per item named after it. So the rule on S3 "Object Created" under `raw/` invokes `aic-prod-knowledge` with `{"action": "start", "bucket", "key"}`; it starts `aic-prod-knowledge-ingest` with name = `item_id`, so a repeated event can't start a second run. Retries 10× over an hour, then an SQS DLQ. The provider (aws ≥ 6.68) already supports S3 Vectors and a Bedrock Knowledge Base on it, so no `awscc` fallback. MediaConvert needs `iam:PassRole`, which the permission boundary used to deny outright: it now allows passing exactly `aic-prod-knowledge-mediaconvert` to MediaConvert and denies passing any other role. The S3 Vectors bucket uses the project KMS key, so the key policy lets `indexing.s3vectors.amazonaws.com` use it.
66. **Knowledge base v2: performance first (the owner's choice, 2026-11-07).** The owner asked for "the most performance optimized RAG and graph databases as well as all other stuff such as lambda functions", accepting about **$615/month fixed** (Stockholm prices, AWS Price List API, 2026-11-07). Supersedes the S3 Vectors and DynamoDB-graph parts of decision 64. Contract: `docs/KNOWLEDGE.md` §1, §4, §9, §10, §14.
    - **Vectors: OpenSearch Serverless, 1 OCU, no standby (~$186/month)** instead of S3 Vectors (~100 ms when searched often, up to 1 s when idle, $0 fixed, meaning-only). OpenSearch answers in tens of ms and supports Bedrock's **hybrid search** (BM25 + vectors; hybrid works only on OpenSearch Serverless, RDS and MongoDB, not S3 Vectors). Trade-off: without a standby replica a failure means a rebuild (AWS re-creates it; the data is re-ingested from S3); with HA it would be ≥ 2 OCU (~$372/month). OCUs scale up under load or with data size, $0.255 per OCU-hour each. HNSW (faiss, m 16, ef 512), float32, 1,024 dims: best recall; fewer dims or binary vectors would save memory, not noticeable time, at personal scale.
    - **Graph: Neptune Analytics, 16 m-NCU, no replica (~$424/month; a replica would double it)**, in-memory, openCypher, the whole expansion in one query instead of many DynamoDB queries. Managed GraphRAG is not in Stockholm, so AI City writes the graph itself (parameterised queries only). Public endpoint with IAM SigV4 auth instead of a VPC: no VPC for Lambdas and AgentCore runtimes (and no NAT cost), the graph is reachable only with the IAM permissions in §9. DynamoDB keeps the item records (key lookups, always-scope index).
    - **No reranker:** Amazon Rerank and Cohere Rerank are not offered in Stockholm; calling Frankfurt would add 150–300 ms and send snippets out of Stockholm.
    - **Direct ingestion** (`IngestKnowledgeBaseDocuments`) per item instead of data-source syncs, so items index in parallel instead of queuing behind one sync job; enrichment runs alongside it (Step Functions Parallel). A full sync remains a manual repair only (AWS says not to run both at once).
    - **Lambdas:** api 1,024 MB with **SnapStart** (~$4/month per GB cached: about $4/month), cutting cold starts from ~1–2 s to a few hundred ms; knowledge Lambda 2,048 MB, reserved concurrency 50; heavy libraries imported lazily; one botocore client per process with a 50-connection pool, keep-alive and adaptive retries. Provisioned concurrency rejected: it only keeps a set number warm (SnapStart covers bursts) and SnapStart can't be combined with it.
    - **Caching:** a 60 s per-process cache of search results (item records always re-read); nothing else, since the query embedding happens inside Bedrock and the prompt cache already holds the stable prompt.
67. **Knowledge v2 infra details (2026-11-07).**
    - **The OpenSearch index is created with the `opensearch-project/opensearch` provider** (`opensearch_index`, SigV4 service `aoss`, the deploy role's credentials, URL = the collection endpoint). Neither hashicorp/aws (6.72) nor awscc (1.109) has an OpenSearch Serverless index resource; a local-exec `curl` would need its own signing. The deploy role gets a data-access rule for `CreateIndex`/`UpdateIndex`/`DescribeIndex` on `items` only (the provider reads the index back with Describe); a `time_sleep` of 60 s lets the data-access policy apply first. Bedrock adds fields to the mapping, so Terraform ignores mapping drift. The provider skips its version ping (`opensearch_version` set), which OpenSearch Serverless doesn't answer.
    - **The collection's network policy is public** (dashboards off), so the GitHub runner can create the index; every call still needs IAM SigV4 and the data-access policy. With `AllowFromPublic` a Bedrock source-service rule is not needed.
    - **SnapStart stays on arm64:** AWS lists Python 3.12+ SnapStart for x86_64 and arm64. The api function publishes a version on every deploy and API Gateway invokes the `live` alias. Its ephemeral storage stays 512 MB (SnapStart's limit).
    - S3 Vectors, its KMS key-policy entry and its boundary actions are removed; `StartIngestionJob`/`GetIngestionJob` are replaced by the direct-ingestion actions; the boundary allows `aoss:APIAccessAll` and the three `neptune-graph:*DataViaQuery` actions (each role's own policy limits them to the one collection or graph).

68. **A native iPhone app with no SDKs (2026-11-07).** The owner asked for an iOS app that does what the HUD does. It is SwiftUI in `ios/` with no third-party packages: Cognito sign-in calls Cognito's public JSON API directly (SRP-6a in Swift, checked against Python big-integer vectors in which a fake server derives the same key; first-login password, TOTP setup and codes, forgot password; refresh with `GetTokensFromRefreshToken`, because the app client has refresh-token rotation on; sign-out with `RevokeToken`). It uses the **same app client** as the web HUD (`ALLOW_USER_SRP_AUTH` only), because SRP needs no callback URL or client secret, so **no infra change** is needed. Amplify Swift was not used: it would be a large dependency, and its refresh path with rotation is not proven. Tokens are in the Keychain (`WhenUnlockedThisDeviceOnly`). The app reads the same public `config.json` from the site (address typed once, or `AIC_SITE_HOST` in `ios/Config/AICity.xcconfig`).
69. **Voice on the iPhone uses Apple's speech APIs, not Transcribe and Polly (2026-11-07).** Push-to-talk uses the Speech framework (on-device recognition when the phone supports it) and replies are read by `AVSpeechSynthesizer`. Calling Transcribe streaming from Swift needs SigV4 and AWS's event-stream framing over WebSocket with identity-pool credentials, which is a lot of hand-written code to keep correct; Apple's APIs need no AWS credentials on the phone, cost nothing and keep the audio on the phone when possible. The trade-offs: no custom "AIC" vocabulary (the app passes "AIC" as a contextual hint instead), the voice is the system voice rather than Polly's, and hands-free wake mode is not built on iOS (push-to-talk only).
70. **The iPhone app's City is the web HUD's own scene (the owner's choice, 2026-11-07).** The owner wants the phone's City to look exactly like the browser's, so the app does not redraw it: `web/src/city/scene.js` and `city-state.js` are built into one small page (`web/city-embed.html`, `npm run build:city-embed -w @aic/web`) and bundled in the app as `ios/AICity/CityWeb/`. A `WKWebView` shows it, locked down: pages come only from the app bundle through a private `aic-city://` scheme that serves just those two files, every other navigation is refused, the page's CSP forbids any network access, the data store is non-persistent, and there are no pop-ups or link previews. The page never sees a token: the app passes it the `/city` snapshot and each WebSocket event as plain values, and the page reports back only what was tapped (`{type, id}`), checked before use. A bundled build was chosen over loading the deployed HUD so no Cognito tokens have to be put into a web page and the City works offline from the last snapshot. A Node test (`tests/city-embed.test.ts`) fails when the scene sources change without rebuilding the bundle, so the two cannot drift apart. Pinch, pan and taps are the scene's own; the web view's page zoom and scrolling are off. Approvals in the app need a 1.2 s hold on a sheet that shows the cost line; VoiceOver users approve with a double-tap on that sheet's Approve element. Supersedes the first, natively drawn City.
71. **Apps the city builds are served from their own origin inside a sandboxed iframe (the owner's request, 2026-11-07).** A game or small feature asked of AIC is built by the Apps department as a self-contained web app and published to a separate bucket (`aic-prod-apps`) behind a second CloudFront distribution with `connect-src 'none'`; the HUD shows it only in `<iframe sandbox="allow-scripts">` (opaque origin: no cookies, no storage, no API), and never listens to its messages. Agent-written code can't reach the owner's tokens even if it tried. The apps CSP's `frame-ancestors` is `https://*.cloudfront.net`, because naming the HUD's exact domain would make the two distributions depend on each other; a custom domain removes that residual risk. Contract: `docs/APPS.md`.
72. **Publishing an app needs the owner, decided by the API, not by an agent (2026-11-07).** Workers submit files to their own workspace prefix (`submit_app`); the apps Lambda validates them (index.html, size, path and type allowlist; content types set by the city) and stages a preview; on the Orchestrator's PASS sign-off the city code (not the prompt) files an `app.publish` approval with the preview. Approving in Needs you makes the owner-only API copy the draft to `live/`; no agent tool can publish or remove an app. Workers and the Orchestrator get no new permissions.
73. **Apps can read the owner's data through a granted, read-only bridge (the owner's requirement, 2026-11-07).** The owner wants to add anything on demand, for example a combined calendar page with a top-bar icon, built as an app rather than a fixed screen. An app's manifest asks for capabilities from one fixed catalogue (calendar, mail search, read-only connector tools); the owner grants them at publish in Needs you and can revoke them later. At runtime the app asks the HUD with `postMessage`; the HUD accepts only messages from the frame it mounted, answers only granted capabilities, and calls an owner-only API route that runs the read through the policy gate as role `app`. The app never sees a token, the API address or the owner's session, and keeps `connect-src 'none'`. Supersedes the "never listens to its messages" part of decision 70. Contract: `docs/APPS.md` § v2.
74. **Apps never act for the owner; they can only propose (2026-11-07).** Nothing that sends, deletes, accepts or changes anything is grantable. An app may propose one of a short list of actions (answer an invitation, create an event, draft a mail); each proposal is a normal approval in Needs you with the same preview as when AIC asks, run once by the API on approve. Pinned apps (up to 6) sit as icons in the top bar.
75. **Connectors are data: any MCP server, added by asking AIC, with sign-in when needed (the owner's requirement, 2026-11-07).** The owner says *"add higgsfield as an MCP"*. AIC's `add_connector` tool (offered only on turns started by an owner message) resolves the URL, or the name through the official MCP Registry, whose content is untrusted. It then files an owner approval bound to the exact URL and roles. Only the owner's yes provisions it. The city then probes the server. OAuth goes through AgentCore Identity: dynamic client registration when offered, a "Sign in to …" button in the chat, a callback on the HUD, and the token stored in the vault under the fixed user `owner`. An API key goes into a secure HUD field that writes to Secrets Manager and an Identity API-key provider; keys are never pasted into chat. Tools work on the next turn without a redeploy. GitHub, Tavily (the owner's search choice; AgentCore's Web Search Tool isn't in eu-north-1) and Slack are added the same way. This replaces the earlier fixed Terraform list (v1, same day). Contract: `docs/CONNECTORS_SKILLS.md`.
76. **Every connector is a Gateway Lambda target on one bridge Lambda, and the Cedar policies are city data.** With a bridge, one owner sign-in serves all four agent roles. Native authorization-code Gateway targets don't document how the user is identified under `AWS_IAM` inbound auth, and are likely per caller. Only the bridge reads credentials, from the Identity vault at call time; runtimes hold only `InvokeGateway`. Checks come in three layers. IAM decides who may call the Gateway. Cedar in AgentCore Policy (`ENFORCE`) sets the ceiling per role; the connectors Lambda rewrites these policies after each change, and Terraform owns the engine only.
