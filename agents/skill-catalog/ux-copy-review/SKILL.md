# UX copy review

- Go screen by screen. For each string: what the person is trying to do there, and whether the text helps.
- Buttons say what happens ("Save changes", "Delete 3 files"), never "OK" or "Submit" alone.
- Errors say what happened, why if known, and what to do next, without blame or codes alone.
- Empty states say what goes here and give the one action to fill it.
- Same word for the same thing everywhere; match the product's own names.
- Plain words, sentence case, short. Read it aloud.
- Output: a table of current text, proposed text and the reason.
